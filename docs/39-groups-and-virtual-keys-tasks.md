## 验证结果

- `cargo test --workspace -- --test-threads=1`：402 passed、12 ignored、37 suites。
- `cargo clippy --workspace --all-targets -- -D warnings`、`cargo fmt --all -- --check`、`git diff --check`：通过。
- Store 覆盖系统资源创建不关联任何组、未分组资源全局管理、按组选择及冲突回滚、共享配置修改、Key 生命周期、摘要存储与聊天历史组归属。
- Gateway 覆盖未分组资源调用拒绝、明确加入组后目录与调用生效、模型与路由独立授权及混合授权、路由授权不开放候选模型别名、跨协议权限边界与即时撤销。
- 控制台覆盖全局 Models / Model Routes 列表不受旧组 Cookie 影响、Key 单组归属、Topcoat 页内提交、CSRF、版本冲突及订阅导入不关联组。
- 浏览器使用独立临时数据库验证：系统列表包含未分组模型；default 初始为空；在应用组明确勾选后数量即时刷新，URL 保持不变；加入组后系统列表仍展示全部模型。
- SQLite 升级保留资源、凭据、引用和自增 ID，同时不自动赋予组调用权限；已运行过开发版关联迁移的数据不会清空现有选择。
- 未配置 `LLMPROXY_TEST_DATABASE_URL`，PostgreSQL 尚未执行实库验证。

## 使用与升级

- 在 `/ui/groups` 管理全部组；Provider 全局共享，Models 和 Model Routes 展示系统列表，从组列表的“模型”“Keys”进入组内页面，添加模型与路由或管理凭据；指定模型和路由均为空时不授予调用权限。
- 外部调用与模型列表接口必须配置虚拟 Key，已有资源保留系统列表，不自动关联 default 组；控制台 Chat 使用内部认证。
- 订阅节点及自动生成的 Provider 全局管理，模型导入到系统列表，再在组内模型页通过「添加模型或路由」明确选择。
