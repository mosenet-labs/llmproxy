### 当前类型层接口

- `protocol::stream::Event`：四种协议的类型化载体及边界结束标记。Messages/Responses 的已知标签严格解析，真正未知的事件保留；Messages 新增未知 delta 同样保留，已知但无效的 delta 不能降级。引用与扩展等开放叶子仍使用 JSON 类型。
- `ir::stream::Event`：通用生命周期、候选、内容块、文本/拒绝/思考、工具字符串增量、签名、媒体、服务端输出、引用、累计统计、字段诊断及失败。候选、输出项与内容块使用独立位置；签名不作为正文。
- `ir::stream::State`：校验生命周期和工具状态。默认保留工具及签名预算为 8 MiB，候选与内容索引最多 1024；普通文本不累积。结束块释放工具参数，失败后不能继续交付正文，结束后仅相同终止标记可重复。
- `ProtocolCodec::stream_decoder(limits)`：每次响应创建独立 `Decoder`，`push(&protocol_event)` 立即返回 IR 增量。协议错配、无语义完成的 EOF、非法序号及超限使本次解码器不可复用。不存在第二个编解码 trait；HTTP、SSE、路由和数据库不进入该模块。
- `ProtocolCodec::stream_encoder(source, target, limits)`：同一 trait 创建四种目标之一的 `Encoder`，`push(&ir_event)` 返回 `Conversion<Vec<protocol::stream::Event>>`。目标 ID、模型与创建时间由接入方提供；正文从 IR 构造，不回填来源报文。失败后不能复用；重复相同结束标记不再次发出终态。
- Messages 先合并原始累计计数，再计算包含缓存读写的输入总数；Gemini 先合并 prompt/candidate/thought 计数，再处理 total。IR 有值覆盖、缺失保留、明确零保留；组件变更且未更新 total 时清除过时合计，不相加重复快照。
- Responses 来源的 `*.done` 与最终快照不重复交付已有正文和参数。来源文本只保留字节计数校验长度，工具参数直接比较；该校验不证明等长文本内容一致。

### 当前目标编码规则

- 四个目标的可见文字在收到 IR 增量时即发出。Chat 的参数字符串逐段发送；Messages、Responses 和 Gemini 当前为补齐晚到名字与完整工具头，在工具结束时发送参数，不等待其他正文结束。Messages/Gemini 必须得到完整 JSON 对象，截断参数或文本工具输入明确拒绝；Responses 可以保留参数字符串，自定义文本工具使用自己的载体。
- Responses 为 `*.done` 和终态完整 `output` 保留类型化副本；快照中的正文及引用与活动工具共用默认 8 MiB 字节预算。引用可在 IR 文本块关闭后补齐，目标项关闭延迟到候选结束，避免引用丢失或快照重复播放。统计的是保留载体的正文长度，结构体开销受条目上限约束；HTTP 序列化长度及背压另由 S5 限制。
- Chat/Gemini 支持多候选；Messages/Responses 固定保留候选 `0`，其他候选告警丢弃，缺少 `0` 时拒绝完成。此规则用于即时输出，区别于非流式在整包中选择最小候选索引；候选以外的总用量仍为上游合计。
- Messages 必填 `message_start.usage` 初始计数采用协议占位 `0`，不会写入编码器的真实 IR 统计；实际累计用量到达后覆盖。完成前必须有真实输入、输出计数，否则拒绝把占位值作为最终用量。Chat 用量在结束分片发送，Responses 在终态快照发送，Gemini 按累计快照更新。缓存读写和 TTL 降级复用非流式规则，不重复相加。
- 同协议 Messages 的思考/签名和引用按类型事件保留，Gemini 工具签名与完整调用在同一 Part 中发送。其他协议签名告警丢弃，跨协议工具回合必须由 S6 保存来源签名状态。跨协议到 Messages 的思考正文作为普通文本告警保留，不能制造签名；Chat 标准事件不支持思考正文，告警丢弃。
- Gateway 将生成失败、无效帧、超时、存储失败和上游断开统一交给父请求失败回调。未发头时返回安全 HTTP JSON 错误；发头后使用客户端协议的错误事件，不追加成功结束。Responses 错误序号延续已发送事件；Chat/Gemini 使用错误 JSON 外壳，Messages 使用 `event: error`。
- 服务端代码、执行结果、搜索正文经过 `ServerOutput` 的公共规则生成目标文本块，并告警专属执行状态、引用和附件的损失。Messages 服务端调用仅关闭原生边界，其参数不伪装成客户端函数；完整结果在 `content_block_start` 投影一次。Responses 服务端进度不输出正文，完成输出项及最终快照去重；MCP 可见输出和已执行的 shell stdout/stderr/退出码复用同一非流式规则。进度必须归属活动原生输出项。
- Chat 音频使用只含音频的类型化原生载体，避免和已经投影的正文重复；同 Chat 编码重建目标外壳。候选结束后仅允许 `expires_at` 尾帧，重复或缺失结束元数据拒绝。Responses 音频和转录分别检查 delta/done，携带 ID 时校验来源 ID；同 Responses 重分配目标 ID 和序号。缺少可移植编码格式时跨协议音频明确拒绝，不能猜格式。
- 图片预览、完整生成图片、客户端电脑操作、MCP 审批、未知原生块或增量等没有等价公共载体时拒绝重建；服务端进度及无可见正文的执行记录告警丢弃。Gemini 回复必须为 model 角色，程序化 Messages 客户端工具调用不能伪装成普通函数。未知外层跨协议事件使用静态路径告警丢弃，同协议重建也不能猜测其索引而复制；现有同协议 HTTP 直通仍保留完整原生与未知事件。
- 字段诊断与语义解码分模块；四协议扩展、候选元数据、logprobs、统计叶子等未映射信息按路径报告。用量扩展及 Responses 外壳诊断与非流式共用函数。诊断在本事件正文前交付，拒绝策略不会先发送本事件工具；单事件诊断的数量和路径/原因字节数受 limits 限制。诊断不包含字段值，累计正文不进入日志。

S1–S8 的基础流式链路已落地，具体 HTTP、真实 Provider 和页面证据见下文。三种来源服务端输出 × 四目标、音频尾帧/独立结束、原生拒绝和扩展诊断继续由类型层专项覆盖；原厂专属能力的真实验收仍按 N2/N3 逐项记录。

### 请求准备与 HTTP 元数据

- `Generation.stream` 表示请求的流式意图。Chat、Responses、Messages 从正文读取并编码；Gemini 由 Gateway 从 `streamGenerateContent` URL 补入 IR，目标编码不向正文添加 `stream` 或 `model` 扩展。`Accept: text/event-stream` 本身不改变请求模式。
- 重建 Chat 流式请求时设置 `stream_options.include_usage=true`，请求结束用量；同协议保留原有 `stream_options`。其他来源专属的 stream options 沿用字段告警策略，不伪造目标选项。
- 跨协议父请求完整解码一次，再从 IR 构造并序列化目标正文、恢复已持久化的 Gemini 工具签名。该过程先于上游请求头；原始输入和转换后的输出各受 8 MiB 限制，准备期间客户端断开会取消存储与转换 future。
- 子请求仍读取原始分块，维持 Pingora 下游输入长度；正文过滤器在结束前输出空字节，结束时只交付一次准备好的目标正文。上游 `Content-Length` 使用目标字节长度，父请求在转交前释放来源 struct 与 IR。
- 上游请求路径、模型、鉴权和头集中在 `proxy::request`。跨协议清除来源查询及协议专属头，按 IR 模式设置目标 `Accept`，请求未压缩输出。Gemini 使用对应方法，规范为一个 `alt=sse`；同协议保留其他查询，清除客户端查询鉴权，使用 Provider 凭据。
- 已解除跨协议流式 422 门槛：父请求使用增量 SSE 转换，子请求复用上游 HTTP、路由和鉴权回调。同协议 SSE 继续按原始字节透传，额外观察来源累计统计。

### Gateway 增量交付和状态边界

- `protocol::stream::sse` 在 HTTP 边界逐字节分帧，处理 BOM、UTF-8 跨块、CR/LF/CRLF、多行 data；仅完整帧进入来源 struct → 事件 IR → 目标 struct。codec 不读取 HTTP 字节。普通文本逐帧交付，不收集整次响应。
- `proxy::streaming::Transfer` 顺序 await 目标帧写入，阻塞期间不继续接收子请求任务，使背压通过框架有界通道到达 Provider。写操作和流内错误发送均使用 Provider 写超时；接收和签名保存期间监视客户端断开，不创建游离转发任务。
- 分帧器的单事件预算为 8 MiB，注释和未知 SSE 字段也计入预算；codec 状态与目标快照各使用 8 MiB/1024 条目限制。签名组的原生 Part 和待交付 IR 合计受 8 MiB/4096 条目限制；单次序列化交付另有 8 MiB 上限。这些是各阶段独立预算，不表示整次请求只使用 8 MiB 内存。
- 协议成功结束事件延后到正常 HTTP EOF。上游已给出协议终态却未给出合法 HTTP 传输结束时仍输出错误；不能把传输断开当作正常结束。子请求失败通知可能先于父请求读取已入队正文，现按正文顺序处理后再报告失败。
- Gemini 普通文字立即交付，函数组等待候选结束及晚到签名。先编码完整组，再保存既有加密状态，成功后发布短引用；三种客户端下一轮通过同一数据库恢复原始 Part。保存失败不发送引用，重启和跨实例不依赖首个 Gateway 内存。
- usage/cache 从来源累计快照记录一次，转换后的占位值不作为 Gateway 上游统计。父请求取消子请求时保留原请求 ID/span 和已收 HTTP 状态，完成日志与用量仍能关联；未获取的连接时间不补造。
- Console 共用分帧及事件 IR；文字、工具参数、媒体和累计用量逐帧更新，正常结束后保存本轮统计。失败/停止会清理未完成的工具展示及用量；签名不展示，展示块不混入下一轮历史。

### 本轮流式验收（2026-10-05）

- 模拟 HTTP：16 个方向各验证文字在 Provider 结束前到达、函数调用及第二轮结果；48 次响应各记录一份累计用量。12 个跨方向覆盖无效帧、协议错误、截断事件、合法协议终态后的传输断开、读取超时和 HTTP 429，错误不包含 Provider 私有正文且不发送成功终态。
- 取消：四个客户端断开后在 2 秒内关闭上游；失败与取消的请求、用量日志关联和单次完成通过。慢客户端在源流完整发送前产生背压并触发写超时；9 MiB 注释事件被单帧上限拒绝。
- 多候选：Chat/Gemini 两种来源到四客户端的 8 个 HTTP 组合验证候选隔离；Messages/Responses 保留候选 0、丢弃其他候选并告警，总用量仍为来源合计。
- 签名：三客户端 Gateway 重启双回合、另一实例恢复、并行调用和晚到签名、保存失败不发布引用通过。真实 Gemini 三个跨协议工具双回合也使用另一 Gateway 实例完成。
