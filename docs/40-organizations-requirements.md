## 已确认要求

- 后续新增组织功能。
- 组织切换器放在控制台顶部 Header，明确显示当前组织；不放在左侧菜单顶部。
- UI 交互必须使用 Topcoat 原生特性。创建、编辑和状态变更使用 procedure 页内提交，以 Signal 管理状态，通过 shard 或响应式页面刷新数据；组织上下文切换属于页面导航。
- 保留现有资源使用流程：导入模型到资源池，再明确选择模型或路由加入资源组，导入或创建时不自动加入 default 或其他组。
- 模型和路由可以被多个资源组复用；虚拟 Key 只能属于一个资源组。
- 资源组详情继续通过 Topcoat 原生 Models / Keys Tabs 管理资源，面包屑保持“控制台 / 资源组 / [资源组名称]详情”。顶部 Header 的组织选择器独立展示，不替换组详情中的所属资源组信息。

## 候选资源关系

建议组织承担资源及成员的管理边界，资源组承担模型调用授权。以下归属方案尚需在实施前确认，不能当作已经实现或全部确认的规则。

| 对象 | 建议关系 |
| --- | --- |
| 用户 | 可以加入多个组织，在各组织分别拥有角色 |
| Provider | 属于一个组织，在组织内共享，不属于资源组 |
| Models / Model Routes | 属于组织资源池，创建或导入不自动加入组 |
| 资源组 | 属于一个组织，只选择本组织资源池中的模型和路由 |
| 虚拟 Key | 只属于一个资源组，通过组确定组织 |

建议第一版禁止跨组织资源引用；路由候选模型也必须来自同一组织。同一模型或路由仍可加入本组织多个资源组，组内模型授权与路由授权继续相互独立。

Provider 范围是实施前必须确定的选择：

- 推荐方案：每个组织独立维护 Provider，组织内资源组共享。当前“全系统共享”相应调整为“组织内共享”。
- 备选方案：平台统一维护 Provider 和模型资源池，再向组织授权资源。此方案需要额外的资源分配关系，不能直接套用上表的归属规则。

订阅节点及其自动生成的 Provider、导入模型的归属，应随最终 Provider 方案统一确定。

## 成员身份与权限候选方案

用户身份、邮箱注册、登录会话和平台用户管理见 [用户登录与管理](41-users-and-authentication.md)。组织成员体系尚待实现；多个团队独立使用时，仍需服务端成员权限校验，不能仅通过页面筛选实现组织隔离。平台管理员角色与组织内角色分别管理。

建议初始角色：

- Owner：管理组织所有权、组织设置与成员。
- Admin：管理组织资源、资源组及 Key。
- Member：使用 Chat 和已开放的模型入口，不管理 Provider 凭据或创建 Key。

登录方式、首位 Owner 初始化方式、成员添加方式、角色权限明细，以及 Member 可使用哪些资源组，均留待实施前确定。虚拟 Key 继续只认证模型调用，不作为控制台登录凭据。

## Header 切换与页面行为

- 顶部 Header 提供组织选择器；有成员体系时仅展示当前用户可访问的组织。
- 切换组织后，Providers、Models、Model Routes、资源组及 Chat 等组织资源页面随之切换范围；组织设置可使用 Topcoat 原生 Tabs 展示基本信息与成员。
- 建议组织切换执行完整导航，重建页面与 Topcoat runtime 上下文。已打开页面和在途 procedure / shard 请求应绑定原组织，不因另一个标签页切换组织而改写操作对象。
- 页面、procedure、shard、WebSocket 连接及相关后台操作都应执行服务端组织归属和成员权限校验。
- 当前资源组仍通过详情入口访问，不恢复公共 Header 的资源组切换器。组织与资源组是两个不同层级的上下文。

## 模型调用与存量数据

在组织隔离方案确定后，建议保持下列兼容规则：

- 外部请求继续使用 Bearer、x-api-key、x-goog-api-key 三种标准认证头，不新增组织认证头，也不绑定特定协议路径。
- 服务端沿“Key → 资源组 → 组织”确定调用范围，不允许客户端传入组织 ID 覆盖 Key 身份；模型列表和实际调用采用一致的组织边界。
- 停用组织后，其全部组和 Key 的新调用立即被拒绝；与现有组及 Key 状态校验共同生效。
- 组织边界覆盖 Chat、历史记录、工具续接、路由快照、后台探活和订阅任务；现有调用日志携带组织标识。
- 升级创建默认组织接纳存量资源，保留原 ID、Provider 凭据、Key、引用及已有组关联；不重新生成 Key，不自动增加组授权。
- SQLite 与 PostgreSQL 均提供迁移及隔离回归验证。
