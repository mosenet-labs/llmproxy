# 组织与资源空间

确认日期：2026-10-10。状态：已实现并完成验证（PostgreSQL 实机验收除外）。

## 使用与资源归属

个人空间和组织空间并列。用户可加入多个组织，各组织分别分配角色。顶部 Header 显示当前空间并提供切换；资源组继续在 Chat、模型及 Keys 的表格中选择。

| 对象 | 归属 |
| --- | --- |
| Provider、订阅节点 | 只属于一个资源空间，不属于资源组 |
| 导入的模型 | 继承 Provider 的空间，导入后进入该空间资源池 |
| Model Route | 只属于一个空间，候选模型必须来自同一空间 |
| 资源组 | 只属于一个空间，明确选择本空间的模型或路由 |
| 虚拟 Key | 只属于一个资源组，通过组确定空间，记录创建人用于审计和撤销 |

模型和路由可加入本空间的多个组。导入模型或创建路由不会自动加入任何组。第一版禁止跨空间共享，不实现组织层级、预算或组织限流。

资源组详情保留 Topcoat Models / Keys Tabs，面包屑为“控制台 / 资源组 / [资源组名称]详情”。顶部空间切换器独立于资源组信息。

## 角色与邀请

邮箱账号、登录会话和平台用户管理沿用 [用户登录与管理](41-users-and-authentication.md)。平台角色与组织角色独立。

| 角色 | 权限 |
| --- | --- |
| Owner | 唯一所有者；管理组织信息、启停、邀请、成员角色及组授权、所有权转移；完整管理业务资源 |
| Admin | 管理组织 Provider、模型、路由、节点、资源组、Keys；查看成员，撤销成员创建的 Keys |
| Member | 在明确授权的资源组内使用 Chat、查看可调用模型和路由；不能管理资源、读取 Provider 凭据或创建 Key |

个人空间本人完整管理。平台管理员保留用户、邮件服务等平台管理权限，并可监督组织；不能访问他人的个人空间。所有权转移必须由现任 Owner 发起，且目标是有效成员；不能直接移除唯一 Owner。

任何有效账号可创建组织，创建者成为 Owner。第一版仅邀请已注册邮箱，发送站内邀请；受邀人登录后在「组织」页面接受，有效期 7 天，不依赖 SMTP。不自动替用户加入组织。Member 加入时不自动授权资源组，由 Owner 明确分配。

## 页面和上下文

- 左侧增加「组织」入口。列表支持创建、查看组织及接受邀请。
- 组织详情使用 Topcoat Tabs：基本信息、成员、邀请；成员无管理权限时只显示基本信息。
- 创建、编辑、邀请、接受邀请、角色/授权变更、移除及撤销使用 Topcoat procedure 页内提交，Signal 管理反馈与刷新。破坏性操作使用原生对话框确认。
- 顶部切换空间执行完整导航，重建页面与 runtime 上下文。组织上下文随 `space` URL 参数传递，runtime 请求使用原页面上下文，服务端重新校验身份与空间权限。
- 不使用共享组织 Cookie 改写其他标签页上下文；原页面及在途请求仍绑定原空间。资源组 Cookie 必须通过当前空间授权组列表校验。
- 不带空间参数时，普通账号稳定进入个人空间；平台管理员进入默认组织。
- 组织内 Chat 历史按用户隔离，缓存命中也检查记录归属；原平台历史保持原归属供默认组织管理员访问。

## 调用与生命周期

- 模型 API 继续接受 Bearer、x-api-key、x-goog-api-key，不与协议 path 绑定。外部客户端不提供组织认证头。
- Key → 资源组 → 资源空间决定模型列表和实际调用范围；不能传入组织 ID 覆盖 Key 身份。
- 停用组织立即拒绝新的 Key 与 Chat 调用；重新启用可恢复。后台快照及定时探活跳过停用组织。
- 组织应用 Key 不因创建人离开组织或被禁用而自动失效。成员管理提供按创建人撤销全部 Keys；移除成员时可明确选择同时撤销。个人账号禁用仍使其个人 Key 失效。
- 组、Key 的已有授权与启停、撤销、过期规则继续生效。组织变更不会扩张已有 Key 授权。
- 工具续接继续绑定调用身份和组；调用日志记录 Key 的空间标识。

## 数据迁移

统一使用 ResourceSpace（personal / organization）。Provider、路由、资源组、节点持有 `space_id`；Models 继承 Provider 空间，Key 继承资源组空间。

平台原空归属资源迁入默认组织；已有个人资源迁入其用户的个人空间。保留原 ID、Provider 加密凭据、Key 秘密、组关联及引用。未关联节点保持未认领，可凭节点密钥认领到当前空间；保留的服务端全局批准流程在启用时将节点归入默认组织。

SQLite 和 PostgreSQL 提供对应迁移。已有平台管理员迁入默认组织，最早管理员成为 Owner；新安装在管理员初始化后补齐默认组织 Owner。升级不重新生成 Key，不自动增加模型或路由的组授权。
