# 模型参考价格规则

关联：[原始需求](00-original-requirements.md) · [模型映射](14-model-mapping.md) · [实施任务](02-tasks.md#b模型参考价格规则)。

## 目标与边界

Models 页面按**已接入的 Provider + 上游模型 ID**管理参考价格。同一上游模型允许有多个客户端别名，这些别名共享价格；价格不属于整个 Provider，也不以别名为唯一价格对象。现有 `model_mappings.input_price_per_million`、`output_price_per_million` 只能表示简单的输入、输出价格，无法表达缓存、峰谷和上下文档位。

首期交付价格的保存、查看和编辑，支持输入、输出、缓存写入、缓存读取、峰谷时段及提示词长度档位。价格仅供展示和后续估算设计使用；本期不向客户端收费，不计算逐请求账单，也不改变模型路由、协议请求体或 SSE 透传。缺少价格显示 `-`，明确填写 `0` 才表示免费。

## 计费项与单位

| 计费项代码 | 含义 | 用量来源示例 |
| --- | --- | --- |
| `input` | 未缓存的输入；DeepSeek 的缓存未命中归入此项 | `prompt_cache_miss_tokens` 或未缓存输入 token |
| `input_cache_write` | 本次写入缓存的输入；可按缓存有效期定价 | Anthropic `cache_creation` 中的 5 分钟或 1 小时 token |
| `input_cache_read` | 本次从缓存读取的输入；DeepSeek 的缓存命中归入此项 | `cache_read_input_tokens` 或 `prompt_cache_hit_tokens` |
| `output` | 本次生成的输出 | 上游返回的输出 token |

缓存**读取仍是输入**，不等于输出。每个模型只填写上游实际支持和计费的项目；例如 DeepSeek 没有独立的缓存写入价格，不应自动建立零价写入规则。首期单位为 `token`，`unit_size=1000000`，单价表示每百万 token 的金额。数据库保留明确的单位字段，不以字段名暗含单位；`token·小时`、调用次数、音频时长等其他计量单位留待对应功能落地时增加。

## 数据模型

### `model_price_plans`：价格版本

| 字段 | 约定 |
| --- | --- |
| `id` | 价格版本主键 |
| `provider_id`、`upstream_model_id` | 价格所属的 Provider 与上游模型；不绑定客户端别名 |
| `currency` | 首期支持人民币 `CNY`、美元 `USD`；同一版本的规则共用币种，不自动换汇 |
| `source_kind`、`source_url`、`recorded_at` | 手动录入、模型目录等来源及采集时间；URL 可为空 |
| `effective_at` | 上游明确公布生效时间时填写；不能把采集时间冒充生效时间 |
| `is_current` | 同一 Provider + 上游模型最多一个当前版本；换价时在事务中归档旧版本并创建新版本 |
| `schedule_json` | 可选的时区、每周峰时时间窗口；无分时价格时为空 |

`recorded_at` 和 `effective_at` 使用 UTC 时间。`schedule_json` 的峰谷时区首期可选 `UTC` 或中国时区 `Asia/Shanghai`，按所选时区填写周几、起止时间；DeepSeek 可用 `UTC`，周一至周五 `01:00–04:00` 与 `06:00–10:00` 为峰时，其余为谷时。此规则不需要全局日历管理。供应商若将来公布指定日期的例外，再增加版本化的日期例外数据；临时修改单价则创建新的价格版本。

### `model_price_rules`：价格行

| 字段 | 约定 |
| --- | --- |
| `price_plan_id` | 所属价格版本 |
| `item_code` | 上表四种计费项之一 |
| `unit_code`、`unit_size` | 首期为 `token`、`1000000` |
| `conditions_json` | 经 Rust 类型校验的条件：`time_band`、`cache_ttl_seconds`、`prompt_tokens_min`、`prompt_tokens_max`；`{}` 表示无附加条件 |
| `unit_price` | 非负十进制字符串；保存时校验，计算时使用十进制数，不经 `f64` 往返 |

同一价格版本内，每种计费项在给定条件下至多命中一条规则。保存时拒绝重复或重叠的条件区间；没有匹配规则表示价格未知，不按零价计算。`conditions_json` 仅接受已定义字段和值，不接受任意表达式。上下文档位按**整次请求的提示词 token 数**判断，例如 `0–200000` 与 `200001` 以上；若将来计算请求价格，同一次请求的输入和输出规则应使用同一档位。

## 规则示例

以下价格于 2026-09-28 查阅官方来源，仅展示存储形状，不作为代码内置价格；使用时应重新核对并保存采集时间。

| 价格版本 | 计费项 | 适用条件 | 单价，USD / 百万 token |
| --- | --- | --- | ---: |
| `deepseek-flash` | `input_cache_read` | `time_band=off_peak` / `peak` | 0.003 / 0.006 |
| `deepseek-flash` | `input` | `time_band=off_peak` / `peak` | 0.15 / 0.30 |
| `deepseek-flash` | `output` | `time_band=off_peak` / `peak` | 0.60 / 1.20 |
| `claude-sonnet-5` | `input` | `{}` | 2.00 |
| `claude-sonnet-5` | `input_cache_write` | `cache_ttl_seconds=300` / `3600` | 2.50 / 4.00 |
| `claude-sonnet-5` | `input_cache_read` | `{}` | 0.20 |
| `claude-sonnet-5` | `output` | `{}` | 10.00 |

每个用 `/` 隔开的条件与价格在数据库中分别保存为两条规则，不能存为单条字符串。上例核对来源：[DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)、[Claude Sonnet 5 价格](https://platform.claude.com/docs/en/models/sonnet-5/overview)。Gemini 2.5 Pro 的提示词长度价格档位可用 `prompt_tokens_min/max` 表示，且其输入和输出都随该档位变化；见 [Gemini API 价格](https://ai.google.dev/gemini-api/docs/pricing)。

## Models 页面交互

列表在协议与状态之间增加「参考价格」列，价格单元格可点击打开独立的价格配置弹窗，不在操作列堆叠新按钮。同一 Provider + 上游模型的多个客户端别名显示同一份价格。显示规则如下：

| 价格状态 | 列表内容 |
| --- | --- |
| 只有无条件的输入、输出价 | `In $0.15 · Out $0.60 / M`，同时标明币种 |
| 存在缓存、峰谷或上下文档位 | 可点击的「按条件计价」；不以最低价冒充通用价格 |
| 尚无价格 | 可点击的「— 设置价格」；不显示为免费 |

批量导入弹窗保留现有紧凑的 `In/Out(M)` 预览：上游目录有简单价格时预填，缺少时显示 `—`。批量导入不展开多行复杂规则；导入后由列表价格单元格进入价格配置。模型别名/协议编辑弹窗只保留价格摘要，不在其中嵌套第二层编辑弹窗。

价格配置弹窗标题使用 `Provider / 上游模型 ID`，提示有多少个客户端别名共用该价格，并标明「参考价格」。顶部集中展示币种、`每 100 万 token` 单位、来源和当前版本；主体为「计费项｜适用条件｜单价」规则表，每条规则独立一行，可新增或移除。`输入`、`缓存写入（输入）`、`缓存读取（输入）`、`输出`使用清晰的中文名称。缓存写入行显示 5 分钟/1 小时有效期字段，上下文档位行显示提示词 token 范围；只有出现峰谷条件时才显示时区和每周峰时窗口编辑区，不增设全局日历页面。

弹窗底部为「取消」「保存新版本」。重叠条件、缺少单价和非法范围在对应规则行直接显示错误并禁用保存，避免只剩一个灰色按钮而没有原因。保存后局部更新所有共享该价格的别名行，并显示包含 Provider 与上游模型 ID 的一次性通知。页面使用 Topcoat 的 Dialog、表单、响应式状态及异步过程实现交互，减少原生 JS。

## 价格发现与旧数据

- `/models` 等上游目录若提供简单输入、输出价格，只在首次导入时预填。已人工保存的价格不因再次探测而自动覆盖；新价格须明确保存为新版本。上游目录没有价格时保持未知。
- 旧价格列若有完整的输入、输出值且同一 Provider + 上游模型的各别名价格一致，可迁为无附加条件的参考规则。若同一上游模型的别名价格相互冲突，不任意选取一个；保留旧值并在控制台标为需人工确认。迁移完成前不能无损删除旧列。

## 后续范围

逐请求费用核算需另行设计上游用量字段适配、价格匹配时刻、实际服务等级、价格版本快照和历史记录。免费额度、套餐、预留容量及平台手续费依赖账户和账期，不属于本期模型参考价格规则；其他单位（`token·小时`、调用次数、音频时长等）在支持对应能力时扩展。
