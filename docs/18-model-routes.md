# Model Routes

Model Routes 将客户端请求体顶层的 `model` 名称映射到一组具体上游模型。候选模型引用 Models 中的记录，因而沿用其 Provider、上游模型 ID、协议配置和参考价格；同一具体模型可被多个路由引用。

`/ui/routes` 展示路由名称、协议、可选候选数量和状态；编辑页先选择一个协议，再在下拉框中搜索并多选支持该协议的具体模型，已选模型在表格中调整顺序或删除。停用 Provider 的模型可搜索但不能新选入。表格中的模型均参与路由。路由名称与协议的组合唯一，同一对外名称可为不同协议分别配置；名称长度为 1–200 个字符。保存使用乐观版本校验，至少需要一个支持路由协议的候选模型。已被路由引用的模型不能直接删除，须先从相关路由移除。

首版采用顺序优先策略。请求协议只匹配同协议的路由，按照候选顺序选择首个参与路由且 Provider 已启用的模型；一个请求选定后固定上游，不在发送后自动切换。未知路由或请求协议与路由不符返回 `404`；路由停用、所有相关候选停用或 Provider 停用返回 `503`。页面中的“可用”表示存在可选的配置目标，不代表推理探测成功。

模型标识保持可直连，不写入 Model Routes 列表；列表只包含显式创建的路由。升级迁移会清除此前自动生成的同名单候选路由，并将保留的跨协议路由按候选模型支持的协议拆成同名路由。路由名称和模型标识不能新建为同名；历史上已扩展的同名路由在同协议下优先于直连标识。删除模型时，若它仍被显式路由引用，须先从该路由移除。

Chat 页的模型选择器同时提供具体模型和当前有可用候选的模型路由。选择路由时会切换到该路由的协议，请求中的 `model` 使用路由名称。

SQLite 与 PostgreSQL 分别使用追加迁移。控制台更改写入数据库后，网关约每秒加载一次不可变快照；每个请求及其 SSE 流始终使用开始时选定的配置。
