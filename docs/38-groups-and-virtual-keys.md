# 组隔离与虚拟 Key

## 已确认范围

Group 是模型资源的隔离边界。Provider 是全局共享的上游配置，不属于组；模型和路由通过多对多关联加入组，系统列表统一维护模型与路由，创建或导入时不自动加入任何组，随后在资源组中明确选择；同一个资源可以被多个组复用。模型与路由的分组互相独立，路由可引用系统中已导入的模型，不会因此把候选模型的直接入口授予路由所在组。虚拟 Key 只属于一个组，授予指定模型与路由或组内全部入口的调用权限，不授予控制台管理权限。第一版保持现有本地管理员模式，不增加成员、角色、预算或限流。

## 数据与管理

新增 groups、virtual_keys、model_group_memberships、route_group_memberships。default（id=1）仅是初始空组，现有模型、路由升级后保留在系统列表，不自动关联组。Provider 全局管理，新建与改名按全局范围校验名称；原分组版中已有的同名 Provider 保留各自 ID、名称、凭据与引用，不自动合并或改名，仍可编辑配置。模型别名在组内唯一，路由名称按组和协议唯一。模型不继承 Provider 的组。组内模型页的「添加模型或路由」弹窗分别勾选系统已有模型和路由，支持搜索；列表中的「移出组」仅解除关联，不删除系统资源；同组重名冲突时整体回滚。共享配置编辑检查所有关联组的命名空间。控制台全局管理模型和路由，模型调用按组关联校验；Key 管理校验单组归属，Provider 的停用、配置与协议变更影响所有引用它的组，删除检查所有组的模型引用。

控制台以资源组（`/ui/groups`）为入口，组列表提供“模型”“Keys”“编辑”，移除“管理资源”操作与左侧独立虚拟 Key 菜单。组内模型页（`/ui/groups/{group_id}/models`）展示本组模型与路由，表头提供类型筛选、搜索和“添加模型或路由”；组内 Keys 页（`/ui/groups/{group_id}/keys`）仅展示本组凭据。两页均明确显示所属组，提供模型 / Keys 相互跳转，面包屑为“控制台 / 资源组 / 模型”和“控制台 / 资源组 / Keys”。组上下文通过页面 URL 与显式 runtime 参数固定，不读取旧 Key Cookie，也不提供切组器；旧 `/ui/keys` 书签按旧 Cookie 跳转到对应组的 Keys 页。Models 和 Model Routes 仍是全系统资源列表，不提供组切换。Chat 在工作区的模型区域选择组，并位于左侧导航第一项。公共顶栏不显示切组器；停用组时提示本组全部 Key 的模型调用将被阻止。

Key 使用安全随机令牌，创建时仅展示一次；存储 SHA-256 摘要、展示前缀、名称、所属组、权限模式、模型 ID 与路由 ID、启用状态、过期时间。从组移出模型或路由时，同时清除本组 Key 对它的指定授权，重新加入后不会恢复旧授权；两类资源均未选择表示无调用权限。全部入口模式显式表达，包含未来加入本组的模型与路由。指定模式分别保存 model_ids 与 route_ids：勾选模型仅开放直接别名，勾选路由仅开放该路由，不自动授权候选模型别名。撤销不可恢复，轮换通过新建再撤销旧 Key 完成。

创建 Key 的授权范围在宽屏横向排列，窄屏自动换行；「可调用资源」按 Models / Model Routes 切换，分别显示当前组资源与数量，跨分类保留勾选。全部入口模式隐藏并禁用指定资源字段。

组与 Key 的 UI 写操作必须使用 Topcoat `procedure` 页内提交，配合 `Signal` 控制提交中状态、错误提示和成功刷新，不使用创建/编辑结果页或页面导航。Key 表格通过 `shard` 局部重新加载；组变更通过 Topcoat 页面响应式重绘更新全部组表格。失败保留表单输入。一次性密钥仅保存在浏览器临时信号中，关闭弹窗立即清空。组内模型增减通过 Topcoat 响应式重绘更新本组表格与弹窗版本，Key shard 显式携带 group_id。Chat 切组仍执行完整导航以重建 Cookie 与 runtime 上下文。

## 请求边界

先认证再解析模型；Key 决定组，不接受客户端指定组覆盖。仅接受三种标准认证方式：OpenAI Chat / Responses 使用 `Authorization: Bearer <Key>`，Anthropic 使用 `x-api-key: <Key>`，Gemini 使用 `x-goog-api-key: <Key>`；不增加自定义认证头，不支持 URL 参数认证。三种认证头归一化，不与特定协议路径绑定；多个不同凭据拒绝。模型列表同样认证并过滤。对外入口和跨协议回退均限制在 Key 所属组及授权模型、路由内；路由内部可选用系统中已导入的候选模型，不开放其模型别名。客户端凭据在上游请求中替换为 Provider 凭据。认证失败 401，无权限 403，不存在模型 404，认证存储不可用 503。

控制台 Chat 同样通过标准 `Authorization: Bearer` 传递服务端内部令牌，并携带服务端确定的组；该通道不向浏览器暴露认证令牌。后台探活和订阅节点控制面保留各自认证，不使用虚拟 Key。订阅节点及其自动生成的 Provider 全局管理；订阅模型同样仅导入系统列表，使用 Topcoat procedure 页内提交，不关联任何组。工具续接作用域绑定组与 Key ID，同一 Key 的不同认证头共用历史，不同 Key 相互隔离。调用日志记录组、Key 和路由标识，不记录令牌。Key 每次请求检查持久化状态以立即响应撤销。

## 升级

已运行过开发版关联迁移的数据库保留现有选择，不清空关联表：历史自动关联与手动勾选没有来源标记，无法可靠区分。可在组内模型页移出不需要的关联。

迁移保留资源 ID、凭据及引用；多组关联迁移不把旧 group_id 转成默认授权，建立空关联表，移除模型与路由的单组列，Key 保留单组外键；新增共享 Provider 迁移移除 Provider 组字段，保留原分组版中的同名记录，以事务内业务校验保证新建及改名不产生全局重名；SQLite 重建受全局唯一约束影响的表，PostgreSQL 调整约束。新增模型授权字段默认空数组，旧指定路由 Key 保持原有路由授权，不自动取得模型调用权限。启用新接口认证后，外部客户端必须配置虚拟 Key；不设置匿名回退。管理员可通过本地控制台创建首个 Key。

## 验收

同名模型与路由在不同组可共存，同一 Provider 可被多个组引用；同一模型与路由可加入多个组，路由可引用未加入当前组的模型；未关联资源可全局管理但不可通过组内 Key 调用，跨组 Key 管理操作拒绝；移出模型或路由清除指定授权；无效、过期、停用、撤销 Key 不可调用；组停用立即拒绝；指定模型与路由权限独立约束目录和跨协议回退；密钥明文不落库；旧库迁移保留数据；控制台 Chat、后台探活、订阅模型导入保持可用。
