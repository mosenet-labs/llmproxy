# 同一对话切换模型与协议

## 设计

会话 ID、历史和标题保持稳定，模型与协议是会话当前选择。每轮开始时在同一把状态锁内固定选择，直到成功、失败或停止后才允许修改；服务端也校验 busy，不能仅依靠页面禁用控件。

展示消息与发送历史分别保存。历史使用 Core 的请求 Message / Item，成功响应通过响应 IR 或流式事件 IR 汇总为有序内容。正文、工具与媒体不从展示标题或 Markdown 反推；usage、思考展示、音频转录和错误提示不混入请求历史。正常结束（含长度上限结束）的内容可提交；停止、失败或 HTTP/SSE 传输截断的响应不提交历史。

发送时构造新的 IR Request，通过 `ProtocolCodec::encode_request(..., EncodeMode::Rebuild)` 得到当前所选协议的请求类型，再由 HTTP 边界序列化。Gemini 模型与流式意图继续放在 URL；Chat 流式请求继续要求结束用量。

每轮独立保存选择、模型别名、响应报告的模型、协议、用量与转换提示，后续切换不覆盖旧轮信息。

## 历史兼容规则

- 文本、拒绝说明及可表达的媒体使用公共 IR；跨来源历史构造时移除协议往返元数据，防止混合协议的原始字段写入目标请求。
- 思考与音频转录继续仅用于展示；签名和私有资源留在本轮结构记录，不能跨模型直接复用。
- 页面不新增工具执行器。完整配对的调用与结果共同发送；未取得结果、重复或无法配对的调用／结果从本轮发送副本中跳过并提示，原历史与页面仍保留。
- 切换模型后私有文件 ID、不透明内容和签名不自动转交。公开可见内容尽量保留；无法映射的内容沿用 Core 的警告或拒绝规则，不编造执行结果。
- 生成中禁止切换模型、协议及历史会话；“新会话”仍用于主动清空上下文。选择失效时保留原选择和历史，并显示原因。

## 验收结果

- Console 单元回归覆盖四协议混合来源历史、两种请求模式、最低序号候选、结构化工具参数与结果数组、错误标志、签名／续传作用域、重复／悬空工具、私有媒体和扩展字段提示。
- HTTP 验收在一个会话内连续完成四协议、流式与非流式，并继续在同一模型内切换四种协议；模拟 Provider 实际接收的正文保留全部已完成轮次。生成中拒绝切换，停止与新会话隔离通过。
- 浏览器完成五轮模型／协议切换、草稿保留、生成中禁用、旧轮模型与 cache/usage、新会话和返回历史、停止后继续；最终构建补验失效 Provider 选择回退、继续跨协议对话及浏览器无错误。全部使用临时 SQLite 与模拟 Provider，人工夹具验收后清理。
- 工作区测试 332 项通过、11 项显式环境／人工用例忽略；Clippy `-D warnings`、格式与 diff 检查通过。

工具配对后使用 Core Codec 的类型转换规范化工具结果叶子，避免 Console 重复解释四协议的结果数组和错误标志。Topcoat shard 保持独立 Signal 绑定；该框架暂不能将这些绑定以 tuple 合并传输。
