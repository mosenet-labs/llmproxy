# 模型定时探活设计

## 范围与复用

第一版验证模型实际推理能力，保存和展示健康状态，不改变路由选择。按模型映射 ID + 上游协议独立配置，默认关闭。复用 llmproxy-probe 的 ModelProber 和现有遥测；控制台共享探测服务负责目标组装、请求、落库，手动与后台任务共同调用。采用服务层 + 存储层分工，无通用任务框架、策略插件或新任务队列。

## 配置与状态

model_health_checks 存储 enabled、interval_seconds（默认 300，范围 30–86400）、timeout_ms（默认 30000，范围 1000–120000）、max_output_tokens（默认 1，范围 1–1024）。模型/协议唯一，删除模型级联删除。最近 ProbeResult 以类型化 JSON 保存（结论、原因、HTTP 状态、耗时、token 消耗、思考模式），不保存响应正文或凭据。

稳定状态与单次结论分离：成功清零失败；明确模型不存在立即不可用；连接失败、超时、5xx 连续三次标为异常；鉴权失败标为鉴权异常；限流、参数与响应不兼容分别显示。结果超过两倍间隔加超时标为过期。模型或 Provider 版本变化时旧结果不可作为当前健康依据，下次调度重新确认。

## 调度与一致性

控制台启动一个后台 worker，每 5 秒查询任务，最多并发四个。MissedTickBehavior::Skip，不补跑历史任务。到期时间加入不超过间隔 10% 的随机偏移。Provider 停用、协议移除时跳过。直接请求目标上游，不通过代理路由。

领取在现有数据库写事务/固定行锁下进行，持久化 lease_until 和 generation；SQLite 用 BEGIN IMMEDIATE，PostgreSQL 复用 route_bindings 写锁。手动探测也领取同一租约，避免重叠。租约覆盖总请求超时并留 10 秒余量，崩溃后自动到期。网络请求期间不持有事务。完成时校验 generation 和模型/Provider 版本，过期执行不覆盖当前结果。配置编辑使旧执行结果失效但保留租约，避免立即产生重叠请求。

后台生命周期由 Console 的共享 RAII guard 管理，最后一个 Console 释放时取消调度及在途任务。请求具有总时间上限。存储错误仅记录受控日志，不泄露 SQL/密钥。手动探测仍可在定时开关关闭时使用。

## 页面与验收

Models 页面探活列仅显示是否配置了定时探活（任一协议启用即为「已配置」）。操作栏「探活配置」打开共用对话框，协议面板默认折叠，标题显示配置状态和探活结果；展开后按协议提供配置、立即探测和刷新，展示当前状态、最近检查/成功时间、耗时与受控原因。页面刷新读取最新结果，不引入浏览器定时轮询。已有编辑器手动探测复用共享服务并落库。

测试覆盖状态转换、参数边界、租约互斥与恢复、过期写入拒绝、配置版本失效、停用/协议移除、模型删除及迁移。使用本地模拟 HTTP 上游验证调度和手动探测共享路径，无真实 API 消耗。完成后统一运行 workspace 测试和格式检查。

## 后续范围

自动故障切换独立实现：需要明确全部目标异常、未知/过期状态的路由语义及恢复策略。本次不修改 gateway 路由选择。

## 使用

升级后重启服务会自动执行迁移。在 `/ui/models` 的右侧操作栏点击「探活配置」，按协议开启定时探活、设置间隔/超时/输出上限并保存。关闭定时开关仍可立即探测。点击「刷新状态」读取最新结果；未开启的模型不会主动产生推理费用。

## 列表状态展示

Provider 停用优先显示「Provider 已停用」。启用但没有任何协议开启定时探活时显示「未探活」，不再将启用配置等同于实际可用。开启的协议结果按模型不可用、连续失败、鉴权异常、探测异常、调用失败待确认、限流、过期、未知、健康的顺序取最需要关注的状态；鼠标悬停显示各开启协议的具体状态。只有所有开启探活的协议均健康时显示「健康」，未开启的协议不参与汇总。该展示不改变代理路由或自动摘除目标。

## Chat 选择器

模型选项只显示名称，路由保留原有路由标识，协议选项只显示协议名称，不附加探活状态；Provider/路由停用、模型明确不存在、路由所有启用候选明确不可用时置灰。连续失败、鉴权异常和模型不存在禁止选择及发送，保留红色提示；限流、单次失败、探测异常和过期以黄色提示，允许继续发送；健康、未探活和未知不显示提示条。手动探测的新鲜结果同样用于判断。已有会话不自动换模型，当前选择不可用时保留并提示重新探测或切换模型。

模型按实际协议独立判断；选取新模型时优先当前协议，明确不可用则选择该模型其他未阻断协议。路由按 provider_protocol 评估上游候选；首选目标不可用时禁止选择并说明尚未自动切换；跨协议网关回退规则见[模型发现与跨协议路由](36-model-discovery-and-protocol-routing.md)。

选择器与发送前校验共用 Chat 目标健康策略；实际生成前再次校验明确不可用状态。发送框上方使用窄提示条，异常时提供刷新、重新探测和切换模型入口，窄屏自动换行。状态在选择切换、发送、显式刷新及探活完成通知时更新，不引入浏览器定时轮询。

## 不可用选择与 Provider 状态同步

Chat 选项在确认不可用（模型不存在、连续三次调用失败、鉴权异常）时以灰色显示并禁用；已有选择和对话保留，不自动换模型。发送前和网关路由共用 HealthStatus::blocks_calls。路由首选目标不可用时同样拒绝选择，因为路由内尚无探活自动切换。

Provider 的启用状态继续表示管理员配置，旁边增加上游健康标签。只汇总已开启探活或已有有效探测结果的模型协议：全部模型不存在显示“模型不可用”；全部确认无法调用显示“上游不可用”；部分失败显示“部分异常”；全部健康显示“探活正常”；瞬时失败显示“上游异常”；未知或过期显示“待确认”，无探活数据显示“未探活”。不会因单个模型不存在自动停用整个 Provider。

探活成功持久化后，通过 watch 通知现有 Topcoat 共享连接。Provider 健康子 shard 更新标签，Chat 健康通知 shard 刷新已有模型选择器与提示；HTTP 首屏仅输出当前快照，无浏览器定时轮询。通知不清空草稿，不切换会话，不重发推理请求。
