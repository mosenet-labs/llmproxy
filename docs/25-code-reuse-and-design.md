# 代码复用与设计优化

## 范围与约束

本轮覆盖 Core、Gateway、Console、Probe 和 Store 的重复规则及接口职责。协议转换继续采用来源协议 struct → IR → 目标协议 struct；JSON 字节只由接入边界处理。各协议原始 DTO 和流式状态保留独立实现，公共算法在实际存在多个调用方时抽离。

## 设计决定

1. 成功探测的 usage 使用 Core 已有的四协议用量适配器，缓存与推理计数沿用 IR 口径。探测特有的宽松响应识别、厂商错误和参数重试保留在 Probe。
2. 同协议 SSE 保留原始字节转发与旁路统计；去掉没有消费者的第二次 JSON 解析，统一使用 Core 的 SSE 边界实现。
3. `ProtocolCodec` 每个方向只有一个整体编码入口，均返回 `Conversion<T>`；调用方必须处理其中的警告。明确传入 `EncodeMode::Preserve` 或 `EncodeMode::Rebuild`。保留模式要求同协议且存在来源副本；重建模式始终按 IR 和目标外壳构造，消息数量变化无需通过删除来源副本触发。
4. 同协议编辑只投影一次来源基线，复用消息、指令、输入项及用量比较；校验投影不再克隆保存整包来源。Gateway 仅观察 IR 的分支保留原始 `Bytes`，实际转换才编码。
5. `protocol::wire` 提供共同的边界解码和不带枚举标签的序列化视图。Gateway、Console 和测试边界复用这些函数；Codec 不接收 JSON 字节。
6. Chat/Responses 的缓存公共字段映射使用小型公共函数；原协议缓存类型、Missing/Null 和厂商扩展继续保留。
7. Console 共用 MIME 预览策略、音频容器识别及附件构造；流式模块只负责分片收集和独立结束，非流式音频使用相同展示规则。
8. Store 内部集中构造 `ActiveProvider`，统一凭据解密、鉴权解析及连接配置复制，调用方继续决定协议、路径和启用状态。
9. Gateway 使用 `SelectedRoute` 组合选路后的必需数据，响应外壳单独组合；正文处理模式使用枚举表达，减少相互依赖的可选状态。Pingora 阶段继续负责 HTTP 及异步 I/O，转换规则留在 Core。

开发时只运行受影响的测试。全部任务完成后统一执行 workspace 测试、Clippy 和格式检查；性能收益仅报告可验证的投影/解析路径减少，不声明未经压测的吞吐提升。

## 完成记录（2026-10-05）

R1–R10 已完成。公共整包 Codec 的调用方已迁移到显式编码模式；历史 JSON 夹具辅助仅保留在 `cfg(test)` 内，不属于生产接口。

- Core：四协议保留往返、16 方向类型转换、无来源构造及显式重建；新增同协议保留来源副本时压缩历史、使用目标响应外壳、模式错误及警告隐私回归。
- Gateway：非流式与流式 16 方向模拟 HTTP、工具双回合、错误、取消、多候选与容量用例通过；同协议 SSE 分块逐字节保留，错误状态不会被观察配置覆盖。
- Probe / Store：宽松探测、参数重试、缓存与推理用量、Provider 路由及鉴权配置读取回归通过。
- Console：流式与非流式媒体策略共用；音频容器预览、未知格式下载、无效 Base64、累计大小限制和生命周期回归通过。
- 完整验证：`cargo test --workspace --offline` 共 **323 项通过、0 项失败、10 项忽略**；忽略项为需显式运行的真实 Provider / OpenObserve 验收和人工浏览器入口，本轮未运行。
- `cargo clippy --workspace --all-targets --offline -- -D warnings`、`cargo fmt --all --check`、`git diff --check` 均通过。

已验证的路径减少：同协议 SSE 不再额外解析无消费者的 JSON；未编辑 JSON 观察路径不再编码；保留编码只生成一份来源基线，校验投影不保存整包来源副本。本轮没有进行吞吐压测。
