# 节假日日历与官方通知导入

## 范围与来源

控制台 `/ui/holidays` 显示日、周、月视图。数据取自[中国政府网《国务院办公厅关于2026年部分节假日安排的通知》](https://www.gov.cn/zhengce/zhengceku/202511/content_7047091.htm)，直接请求原网页，不使用第三方节假日 API。按照通知的**完整放假调休区间**逐日入库，并把通知指定的周末调休上班日单独存储；普通周末没有官方特别安排时不写入记录。

当前官方来源固定为 2026 年通知。页面可以浏览其他年份，但只有核对该年度官方通知及文号后才开放相应年度的导入。这样能在通知格式变化时避免误导入。

## 数据与导入

`holiday_dates` 以 `YYYY-MM-DD` 为主键，保存年份、节日名称、`holiday` / `adjusted_workday`、官方来源 URL 与导入时间。SQLite、PostgreSQL 使用各自的追加迁移。

导入先检查官方网页的标题、文号和七个节日段落，再核对每个放假区间与通知声称的天数，最后检查日期重复。任何一步失败都不修改数据库。全部解析成功后，在单个事务中替换 2026 年记录；重复导入可用于同步官方更正。

## UI 与组件边界

通用 `calendar` 组件位于 `topcoat-ant-design`，负责日期网格、事件与语义状态。`llmproxy-console` 负责查询数据、导航日期和导入。切换日/周/月、上一时段/下一时段和导入反馈均使用 Topcoat 的 Signal、Shard、Procedure 与 Notification，没有添加原生 JavaScript。

模型价格日程可勾选「中国放假安排全天按谷时」。时间先按价格日程的时区和每周窗口判断；命中峰时窗口时，再用中国日期查询该年份日历：`holiday` 改判谷时，`adjusted_workday` 不改变每周窗口规则，普通周末无峰时窗口时为谷时。命中峰时窗口但年份未导入时，预览明确显示「无法判断」。价格仅作参考展示，尚不用于逐请求费用核算。详见[模型参考价格规则](16-model-pricing.md)。
