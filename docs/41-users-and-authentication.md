# 邮箱注册、登录与用户管理

状态：已实现。组织功能仍按 [组织需求](40-organizations-requirements.md) 后续实现。

## 功能范围

- 邮箱注册、邮箱和密码登录、退出、邮件验证码验证、密码找回及个人账户设置。
- 注册需要证明邮箱所有权，不自动取得管理员权限；未配置 SMTP 时关闭注册、找回和发送重置邮件，并明确提示。
- 注册仅填写邮箱、验证码、密码及确认密码，默认账号名称为完整的规范化邮箱地址，可在个人账户中修改显示名称。
- 平台角色为管理员与普通用户。管理员管理现有系统资源及用户；普通用户暂时只可管理个人账户，不开放 Provider、模型、资源组、Keys、Chat 或历史记录，业务授权留待组织模块。
- 没有管理员时，登录页默认展示“初始化管理员”入口，填写邮箱、密码和确认密码即可创建首个管理员并自动登录，无需命令行、SMTP 或邮件验证码。初始化后入口关闭；服务端在事务中再次检查，仅允许一次初始化，包括并发请求。公开邮箱注册不会生成管理员。
- 用户管理提供搜索、角色和状态筛选、紧凑表格、分页及每页记录数；可编辑显示名称和平台角色、启用/禁用、注销全部会话、发送密码重置邮件。
- 禁止禁用或降级最后一个有效管理员；本期不提供用户永久删除或管理员直接设置他人密码。
- Header 右侧以链接样式显示登录账号名称，点击展开账户菜单；第一项为个人账户，最后一项为退出。后续组织切换器仍放顶部 Header。
- 左侧菜单底部提供仅管理员可见的「系统设置」，邮件服务为平台级设置，不属于资源组或个人账户。

## 身份与会话

SQLite 与 PostgreSQL 提供一致迁移，账户数据独立于资源组：

| 模型 | 关键字段及约束 |
| --- | --- |
| users | id、唯一邮箱、显示名称、密码哈希、平台角色、启用状态、邮箱验证状态、注册/更新时间、最近登录时间、乐观锁 version |
| user_sessions | 令牌摘要主键、user_id 外键、会话 CSRF、创建/活动/绝对过期时间；不保存明文会话令牌 |
| email_challenges | 用途与规范化邮箱组成唯一 scope、绑定 scope 加密的验证码、创建/过期时间、尝试次数和已使用状态 |
| mail_settings | 单例平台邮件配置：启用状态、SMTP 主机/端口/TLS、发件邮箱、用户名、加密密码及乐观锁 version |

发送注册邮件时创建未验证账户，验证通过后设置密码哈希并激活邮箱；没有自动管理员提升。用户身份以后通过 user_id 加入组织成员关系，组织内角色独立于平台角色。

用户邮箱采用一致的去空白、大小写归一化策略和唯一约束，不移除加号后缀或邮箱中的点。

密码使用带随机盐的 Argon2id 哈希，最少 15 个字符、最多 128 个字符；哈希运算放入受限并发的 blocking 任务，避免阻塞异步请求。密码和验证码不记录日志。

服务端保存随机会话令牌的摘要，Cookie 设置 HttpOnly、SameSite，HTTPS 部署启用 Secure；会话绝对有效期为 7 天，连续 24 小时未活动过期。登录轮换会话，写请求使用会话绑定的 CSRF 校验。退出、密码重置、账户禁用、权限变更和管理员注销会话立即撤销对应会话。

页面、procedure、shard 和 WebSocket 握手及后续执行均进行服务端校验。WebSocket 后台每秒复查会话撤权状态，复查不延长空闲有效期。现有虚拟 Key 继续用于模型 API，不能登录控制台；控制台 Cookie 不能替代虚拟 Key 调用模型。

## 邮件与频率控制

注册和找回密码使用 6 位验证码，有效期 10 分钟、最多 5 次校验，发送间隔至少 60 秒，并限制邮箱与客户端的请求频率。验证码用途隔离、单次消费，服务端保护存储；重复注册和不存在邮箱的找回请求采用一致回复。重新发送使旧验证码失效。

管理员在「系统设置 → 邮件服务」(`/ui/settings`) 配置服务器、端口、用户名、密码、发件邮箱及 TLS 模式，可启停并向指定收件邮箱发送测试邮件。配置写入数据库，保存后立即生效，无需重启；每次发送及注册/找回请求读取最新状态。SMTP 环境变量已移除，不再读取或作为回退，已有部署须在页面重新填写原配置。

密码使用数据库主密钥和独立业务关联数据加密，公开视图只提供是否已配置，不回显明文或密文；编辑时密码留空保留，清空用户名则清除已存密码并使用无认证 SMTP。设置保存及测试 procedure 均要求管理员身份和会话 CSRF；Store 写事务再次验证管理员权限，并以版本号防止覆盖其他管理员的更新。

允许本地回环 SMTP 测试服务使用明文，外部 SMTP 必须使用 TLS；测试不会发往真实邮件服务。可配置可信控制台公开地址以支持 HTTPS 反向代理，不能根据请求 Host 拼接任意外部地址。

## Topcoat 页面与交互

- 登录页使用 Topcoat 原生 Tabs 展示登录、注册和找回密码流程，表单有明确字段、提交状态和页内错误。
- 注册成功通过 Signal 自动切换到登录表单，带入刚注册的邮箱并显示成功提示，清空验证码和密码；失败留在注册表单，URL 不变。
- 首次管理员初始化也通过 Topcoat procedure 页内提交，复用密码确认、频率控制、CSRF 和会话签发逻辑；失败保留表单并显示错误，成功设置会话 Cookie 后进入 Chat。
- 初始化、注册、找回和修改密码共用密码字段；输入不一致时在确认密码下方显示错误并阻止提交，修改任一密码后重新校验，匹配后清除错误。密码长度要求常驻显示，服务端继续校验。
- Header 使用 Topcoat 原生 Dropdown Menu；退出通过 procedure 提交。
- 个人账户以单张资料卡展示邮箱、平台角色和显示名称，支持页内保存名称；点击“修改密码”打开 Topcoat 原生 Dialog，复用密码确认及提交状态，修改成功后注销全部会话并返回登录页。
- 用户管理使用现有紧凑 data_table、分页控件及原生编辑弹窗。
- 系统设置使用 Topcoat procedure 页内保存、Signal 反馈与响应式刷新，邮件配置和测试发送为独立表单；普通用户隐藏设置入口，并拒绝页面和 procedure 访问。
- 资源与账户写操作通过 procedure 页内提交，Signal 管理状态，shard 或响应式刷新列表；身份变化后的导航用于重建会话上下文，不增加写操作结果页。
- 沿用现有控制台的紧凑布局、面包屑和字体；不增加重复大标题。普通用户不显示管理员菜单。

## 模块职责

- `llmproxy-store::auth`：公开账户视图和输入规范；数据库 Row 在 `model` 中定义。
- `store::auth::{users,password,sessions,challenges}`：账户生命周期、密码哈希、会话及邮件验证；共用邮箱规范化、事务权限校验、随机令牌及摘要逻辑。`store::settings` 独立维护平台邮件配置，复用管理员权限检查；`llmproxy-store::settings` 分离公开配置视图、只写密码输入和内部发送凭据。
- `console::app::auth::{procedures,mail,rate}`：请求身份/角色校验、SMTP、频率控制及账户 procedure。
- `ui::{login,account,users,settings}`：认证 Tabs、个人账户、用户管理及系统设置；`settings::procedures` 独立处理配置和测试发送，`account::password` 独立封装修改密码弹窗，`ui::forms` 复用密码字段、强类型 procedure 提交状态和反馈，分页复用 `ui::table`。
- Gateway 只适配客户端地址及 WebSocket 会话复查；凭据验证归 Store，避免在 UI、传输层重复实现账户规则。

## 迁移与验收

账户迁移不修改现有 Provider、模型、路由、资源组、虚拟 Key 和 Chat 数据；升级后控制台要求登录，在登录页初始化管理员后访问存量资源。默认无匿名管理回退。

验收覆盖注册与找回完整流程、验证码重放/过期/错误次数/用途隔离、密码哈希、会话失效、CSRF、角色权限、最后管理员保护、WebSocket 撤权、普通用户数据隔离、无 SMTP 提示及现有虚拟 Key 接口回归。浏览器验证使用隔离数据库和本地测试邮箱。
